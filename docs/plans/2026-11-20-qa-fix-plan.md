## 핵심 발견 3가지
1. **ODsay 무료(Basic)는 하루 30콜**. 지금 검색 1회 = 경로 1 + loadLane 1 = 2콜, 실패 시 직접→프록시 폴백 × react-query 재시도 = 최대 8콜. 사실상 하루 10여 회 검색이면 끝 → 대중교통이 "가끔 안 되는" 근본 원인.
2. **대중교통 소요시간이 과대 표시**: `transitChain.ts:34-37`이 도보 포함 모든 leg 사이에 5분을 더함. 구디→강남 실측: 단계 합 23분인데 카드 33분(3 leg → +10분). 도착시각도 같이 틀림.
3. **데스크톱에서 패널이 열려 있으면 지도 조작 불가**(휠·드래그·클릭·FAB). transparentModal 레이어가 전체 화면 입력을 가로챔.

## P1 — 버그·나쁜 UX
- **구디 → 구로디지털단지역 안 나옴**(사용자 요청 항목, 11-18 "카카오가 처리" 판단이 틀림. 라이브 확인: `구디`→구디별밤·구디·구디야시장, `가디`→가디, `고터`→광명종합터미널 1위; `구디역`만 정상) → 소규모 별칭 사전(구디·가디·고터·서울대입구 등) 서버 정규화 + 테스트
- 위치 거부 시 "내 위치" 무반응 → 권한 안내 토스트
- 장소에서 뒤로가기 → 홈으로 감 → 검색 결과로 복귀(history replace 제거)
- 데스크톱: 장소→도착 시 이전 장소 카드가 경로 입력 아래 비침(겹침)
- 키보드: Esc 닫기, 패널 열 때 포커스 이동, 결과 방향키·Enter
- 경로 결과 화면만 헤더+고정 패널 → 다른 화면처럼 시트/카드로 통일(도보 결과 80% 빈 패널 해소)
- 경로 입력 검색: 로딩/에러를 "결과 없음"으로 표시 + 프록시가 공급자 실패를 `200 []`로 숨김 → 502
- 웹 카카오 SDK 실패/타임아웃 시 MapLibre 폴백(현재 빈 지도 영구) — "카카오 안 되면 전환" 원칙
- fetch 타임아웃 누락(apiClient·ODsay) → 무한 "탐색 중" 가능
- URL에 preference/maxExtraMinutes 미보존, 재탐색 시 경유지 누락, swap 시 경유지 역순 안 됨
- `google:` 장소가 좌표 0,0 + 미지 provider 무검증 → 400·힌트 좌표 사용
- 시트: 빠른 드래그가 60%를 건너뛰어 90%로(pickSnap 기준점), 30%로 내리면 스크롤 유지돼 제목 가림, 핸들 스크린리더 조작 불가
